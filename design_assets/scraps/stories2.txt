General Description Details the user stories for NovaID's four foundational journeys: account
provisioning, activation and login for every user type (from the initial NICRA
National Administrator bootstrap through staff, institutional and citizen access),
birth registration via a OneHealth-connected facility, naturalized citizen
registration, and identity correction / material change. Written from the NovaID
PRD (Working Draft 0.6) for developers, QA testers and product managers.
Target Audience Developers | QA Testers | Product Managers
REVIEW AND APPROVAL
Created By: Gio (Product Manager, NovaID)
NOTE — DATE AND TIMESTAMP DISPLAY CONVENTION
● Date of birth is always displayed as YYYY-MM-DD (ISO 8601), on every screen and in every story
in this suite, with no exceptions.
● All system-generated dates — registration date, notification date, approval date, audit-log
timestamps, and similar — display as MM/DD/YYYY for the date portion. Time displays in 12-hour
(hh:mm:ss AM/PM) or 24-hour (HH:mm:ss) format per user or device preference, but is always
stored in 24-hour canonical form.
● These are two different, deliberate formats for two different kinds of date — a citizen's date of
birth versus a system event date — not an inconsistency. Any screen showing both together (for
example, a registration form or a profile dashboard) must keep the distinction visible, e.g. by
labelling the field clearly, so it never reads as a formatting bug.
● Source: Novaria_Platform_Reference.xlsx, System Conventions sheet.

● Facility/officer authorisation is
